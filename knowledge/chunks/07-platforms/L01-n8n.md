## Claims

- n8n's **AI Agent node** turns one step of a workflow into an agent: connect
  a chat model and at least one tool, and the agent decides which tools to
  call. [n8n-docs-ai-agent §AI Agent node]
- Since n8n 1.82.0 every AI Agent node works as a "Tools Agent"; the old
  agent-type setting is deprecated and the v1 node will be removed in n8n
  3.0. [n8n-docs-ai-agent §Feature availability]
- The Tools Agent supports chat models from OpenAI, Anthropic, Groq, Mistral
  and Azure AI Foundry, and can use n8n's app nodes (Gmail, Google Sheets,
  HubSpot, Jira, Outlook and many others), an HTTP request, code, or another
  n8n workflow as tools. [n8n-docs-ai-agent, Tools Agent page, supported models and tools]
- **MCP both ways** [n8n-docs-mcp-nodes]:
  - the **MCP Client Tool** node lets an n8n agent use tools from an outside
    MCP server. It can expose all of the server's tools, only selected ones,
    or all except some. (§MCP Client Tool, Node parameters)
  - the **MCP Server Trigger** node makes n8n itself an MCP server, so
    outside AI clients can call n8n tools and whole workflows. It offers no
    authentication, bearer or header authentication.
    (§MCP Server Trigger, How it works; Authentication)
- **Licence.** n8n's main code is under the "Sustainable Use License". It
  allows use and modification "only for your own internal business purposes"
  or non-commercial or personal use, and free distribution only for
  non-commercial purposes. Files marked `.ee` need a paid Enterprise licence.
  [n8n-2026-license §Limitations; preamble]

## Where sources disagree

- Not a disagreement, but a version gap: n8n's MCP Client Tool asks for an
  "SSE Endpoint". The current MCP spec (2026-07-28) classes the HTTP+SSE
  transport as deprecated in favour of Streamable HTTP.
  [n8n-docs-mcp-nodes §MCP Client Tool; mcp-2026-spec §Key Changes, Deprecated 2]
  n8n's trigger node already supports Streamable HTTP.

## Not verified

- n8n's hosting options, resource needs and cloud prices: docs.n8n.io and
  n8n.io were blocked from this environment, and the comparison article by
  selfhosting.sh (dev.to) could not be opened. Claims about them are not
  made here.

## What this means for the guide

- n8n fits work whose steps are mostly fixed and triggered by events or
  schedules, with an agent step only where judgement is needed. This is the
  hybrid pattern in F02.
- When an agent step needs the business's software, prefer n8n's own app
  nodes as tools; use the MCP Client Tool for systems n8n lacks. Use
  "Selected" tools rather than "All" (least privilege, T04).
- n8n's MCP Server Trigger is how a Claude or Hermes agent can call a
  dependable n8n workflow as a single tool. If used, turn on authentication.
- **Licence check for the guide:** "open-source" is not accurate for n8n;
  it is source-available under a licence that restricts commercial resale.
  A business using it internally is fine; one building a product for
  clients on it should check the licence.
